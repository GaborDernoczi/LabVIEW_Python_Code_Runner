# LabVIEW_Python_Code_Runner

A minimal example that shows how to call a Python function from LabVIEW using the built-in
**Python Node** (Connectivity » Python palette).

<img width="1576" height="1265" alt="image" src="https://github-playground.int.automotive-wan.com/user-attachments/assets/59a57dc1-ddc7-4635-bdec-c9c0d2bb0fb3" />

## Requirements

| Component | Version |
| --------- | ------- |
| LabVIEW   | 2020 (32-bit) |
| Python    | 3.6.8 (32-bit)|

> **Important:** the bitness of the Python installation must match the bitness of LabVIEW.
> A 32-bit LabVIEW can only load a 32-bit Python interpreter, and a 64-bit LabVIEW only a
> 64-bit one. LabVIEW 2020 supports Python 3.6, so Python 3.6.8 is the recommended runtime.

## Files

| File | Description |
| ---- | ----------- |
| `Python_LabVIEW.vi` | The LabVIEW VI that opens a Python session, calls the function and closes the session. |
| `Python_LabVIEW.py` | The Python module containing the `LabVIEW()` function that is called. |
| `Python_LabVIEW.lvproj` | LabVIEW project file, including a build specification for a stand-alone executable. |
| `Python_LabVIEW.aliases` | Project aliases file generated by LabVIEW. |

## How it works

The VI uses three nodes from the **Connectivity » Python** palette:

1. **Open Python Session** – specify the Python version (`3.6`) and, optionally, the full path
   to the Python DLL. It returns a Python session reference.
2. **Python Node** – provide the path of the `.py` module (`Python_LabVIEW.py`), the function
   name (`LabVIEW`), the input parameters and the return type. The data type wired to the
   return terminal determines how LabVIEW converts the Python return value.
3. **Close Python Session** – releases the interpreter and frees the resources.

Errors are propagated through the standard error cluster wires between the nodes.

## Usage

1. Install Python 3.6.8 with the bitness matching your LabVIEW installation.
2. Open `Python_LabVIEW.lvproj` in LabVIEW 2020.
3. Open `Python_LabVIEW.vi`.
4. Make sure the module path on the block diagram points to `Python_LabVIEW.py`
   (use a relative path or `Current VI's Path` so it also works after building).
5. Enter values into `Input1`, `Input2` and `Input3` on the front panel.
6. Run the VI – the indicator shows the sum returned by the Python function.

## Building an executable

The project contains a build specification named **Python_LabVIEW** that creates
`Application.exe` in `builds/NI_AB_PROJECTNAME/Python_LabVIEW`.

When building, remember that the `.py` file is **not** embedded in the executable. Add it to
the *Always Included* items of the build specification so it is copied next to the executable
(into the `data` folder), and resolve its path at run time, for example by deriving it from
`Application Directory`.

## Troubleshooting

| Symptom | Cause / Solution |
| ------- | ---------------- |
| Python failed to load | Wrong bitness, or the selected Python version is not installed. Verify that LabVIEW and Python have the same bitness. |
| Unable to load the module | The path of the `.py` file is wrong, or the module raises an error on import. |
| Function not found | The function name is misspelled, or it is not defined at module level. |
| Type conversion error | The LabVIEW data type of an input or of the return terminal does not match the Python type. |
| Crash on close | Do not close the session while another Python Node is still running; keep the error wires connected to enforce execution order. |

## Notes

- The `print()` output of the Python function goes to the standard output of the process,
  which is not visible in the LabVIEW IDE. Return the value instead if you need to display it.
- Only one interpreter version can be loaded per LabVIEW process. Restart LabVIEW to switch
  to a different Python version.
